# 레포 지도

이 사람이 일하는 레포들의 위치와 역할, 서로 어떻게 이어지는지가 지도에 있다.

```sh
~/.julgi/bin/julgi map            # 지도 전체: 레포마다 경로, 하는 일, 무엇을 찾을 때 보는지, 레포끼리의 관계
~/.julgi/bin/julgi map "앱"       # 이름이나 설명에 글이 있는 레포만
```

지도에는 레포마다 역할(백엔드 서버, 앱, 웹 화면, 게이트웨이, 공용 모듈·계약, 배포 설정 등), 이어진 곳(누가 누구를 부르고 무엇에 기대는지), **바꿀 때 같이 볼 곳**이 적혀 있다.

- 다른 레포를 읽어야 답할 수 있을 때 지도에서 그 레포를 찾아간다.
- API 응답, 메시지 형식, 계약 파일처럼 밖에서 쓰는 것을 바꾸기 전에는 "바꿀 때 같이 볼 곳"을 보고, 거기 적힌 레포의 해당 부분을 실제로 읽어 영향이 있는지 확인한다. 확인한 결과를 사용자에게 알린다.

지도의 "## 도메인"에는 영역별 묶음이 있다. 사용자가 "어드민 쪽", "판매자 쪽", "고객 앱 쪽"이라고 하면 여기서 그 영역을 이루는 조각(화면, 서버 모듈, 계약)이 어느 레포의 어느 폴더인지 찾는다. 한 레포 안에 여러 영역이 들어 있는 경우가 있으니 레포 이름만으로 짐작하지 않는다.

## 쓰는 법

1. 지도에서 봐야 할 레포를 고른다. 경로가 적혀 있다.
2. 그 경로를 직접 읽는다(Read, Grep, Glob). 지도에 있는 레포는 이 세션에서 읽을 수 있게 열려 있다.
3. 지도에 없는 레포거나 경로가 실제와 다르면 그때 사용자에게 묻는다.

다른 레포는 읽기만 한다. 고쳐야 하면 `julgi send`로 그 레포의 줄기에 넘긴다.
